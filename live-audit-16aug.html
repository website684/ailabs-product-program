Where to look: registry GET-by-id for fresh drafts and the Redis config cache (agent:{org_id}:{agent_id}) — a mis-keyed cache write on create, or an id-ignoring fallback on read, fits every symptom. Add a regression test: create draft → GET by id → assert name matches. Consider an FE assert too: if response.agentId ≠ route.agentId, refuse to render and log.

P1 — trust & flow

P1Every failure wears the same mask: "Something went wrong"

QA/UAT backends were fully down (502 on every ghost-operators call). The UI showed the identical generic copy for: login failure, registry load, agent summary, and create — four different failures, one message, plus stacked duplicate toasts and an inline error saying the same thing a third time.

login POST → 502 → "Something went wrong. Please try again." GET /agents, /agents/summary → 502 → two toasts + inline empty-state, all generic POST /agents → 502 → toast "Create agent failed / Failed to create agent" (title = body)
Fix: map gateway-level failures (502/503/timeout) to a distinct "platform unreachable" state with a status link — retrying can't help and the copy shouldn't pretend it might. Deduplicate toast+inline. Error titles and bodies must not repeat each other.
P1"Create & Continue" doesn't continue

The wizard shows a 5-step rail (7 for Orchestrator: Name it → How it talks → What it knows → Safety → Build → DAG → Review), but Create & Continue creates the draft and exits to the read-only detail page. Steps 2–7 never happen in the flow that advertised them; configuration requires finding "Edit Configuration" and re-entering a builder that repeats step 1.

Fix: either continue into step 2 with the draft saved in the background (best), or rename the button and drop the step rail from the create screen. The rail is currently a broken promise at the exact moment of highest intent.
P1Draft agents can't be tested (confirmed live)

"Test Run" is disabled for drafts in the registry (Recruitement agent row) with no explanation of what would unlock it. Predicted by the April review; still true. Testing is how builders learn — forcing publish-to-test inverts the loop.

Fix: sandbox test for drafts (the Templates PRD's preflight/sandbox machinery is the same investment). Interim: tooltip stating exactly why it's disabled and what to complete.

P2 — copy & polish

P2Raw template variable shown to admins

Default greeting renders as Hi, I am {agent_name}. How can I help you today? — the placeholder is neither substituted nor explained on the detail page.

P2"Not visible to end users" is not true

Profile section: "How operators recognize this agent. Not visible to end users." The agent name/avatar surface in the embedded chat header. Same misleading copy our static audit flagged in March-era code — still shipping.

P2ACTIVE = 0 while 20 agents are Published

The stat row reads Total 26 · Published 20 · Draft 6 · Active 0. Whatever "Active" measures, showing zero next to twenty published agents reads as either broken telemetry or a damning adoption metric. Neither belongs on the default screen unexplained.

P2Raw "DAG" in the primary wizard nav; type descriptions never say the word "workflow" plainly

Orchestrator's step rail includes a step literally named "DAG". The type card says "a chat + widget interface over a DAG" — good copy otherwise, but the one term the target admin won't know is the one left unexplained. ("Recruitement agent" typo in prod registry data is a reminder that no spellcheck/nudge exists on names.)

P2Registry rows aren't clickable; wizard rail isn't either

Clicking an agent row does nothing (only the name text navigates); clicking a step in the builder's progress rail does nothing (Next-only navigation). Both look interactive and aren't.

P2Readiness banner counts problems it won't name

"This agent isn't ready to publish. 1 thing left to do: Complete setup in the Builder" — the right pattern (blockers surfaced on the detail page) undermined by refusing to say which thing. Link the actual gate.

GOODBuilder handles variables properly — only the detail page doesn't

"How it talks" offers +User Name / +Email ID / +Agent Name chips and explains runtime substitution; "What it knows" cleanly splits KB / Tools / MCP with agent-level vs per-step scoping notes. The P2 above is a detail-page rendering gap, not a platform gap.

What the current build gets right

GOODWorth keeping as-is

· Two-type simplification (Chat only Bot / Agent Orchestrator) with honest use-case descriptions — better than the old three-way split.
· Plain-language step rail (Name it / How it talks / What it knows / Safety) — the exact renaming our redesign proposed, already live.
· Type switch preserves entered fields; type locked after creation with a clear explanation line.
· Guardrails on detail page show org inheritance per flag ("Inherit (org: on)") — effective-value transparency done right.
· Create form kept all input through a full backend failure (QA) — no data loss on error.
· Unsaved-changes guard on builder navigation (it even caught the P0's corrupted hydration).

Strengthened recommendation set: (1) fix the P0 id-resolution bug and add the regression test before anything else; (2) failure-state taxonomy — platform-down vs validation vs permission, each with distinct copy; (3) make Create & Continue continue; (4) draft sandbox testing (doubles as Templates preflight); (5) the terminology pass (DAG, Active, placeholder rendering) from the existing 144-item backlog. Items 2–5 are the same "missing translation" theme as the static audit — now with production evidence attached.
