Crew Onboarding & Verification — Subway

UAT · PROTOTYPE

How AI Labs powers the candidate experience end-to-end: one conversational agent for the candidate, one workflow agent for verification, existing widgets for every interaction. This page is the team-facing map — flip through the tabs.

Candidate journey — 8 stages, one thread

Research-backed flow (63 findings, 8 dimensions — see blueprint doc). Every stage lives in one chat; nothing requires a login or app install.

1
White-label entry

Offer link on WhatsApp/SMS → branded landing → language picked once, persists everywhere.

chat apply ≈92% step conversion vs ≈20% portal forms
2
Consent gate

Itemized, plain-language, timestamped — before any data is collected. Withdraw path always available.

DPDP Rules 2025 / PDPA hard requirement
3
Confirm-don't-retype details

Agent shows what it knows from the ATS; candidate corrects, never re-keys.

4
Document capture + OCR

Guided camera capture, client-side quality gate, extracted fields shown for confirmation. DPI waterfall where available (DigiLocker / MyDigital ID / Dukcapil / Singpass) skips capture entirely.

assisted capture cuts blur/glare rejects up to 70%
5
Selfie liveness + face match

Passive liveness (no gestures), separate biometric opt-in, retention microcopy under the camera.

6
Background checks — async

Consent → dispatch to workflow pipeline → 3-state candidate status. Slow checks never block the journey.

criminal checks 2–7 days — must run in background
7
AI interview + training reels

Structured scored questions (text/voice), then Skilling reels with MCQ frames inline in chat.

chat microlearning ≈85% completion vs 20–30% LMS
8
Done → Day 1 nudges

Verified crew ID, HRMS webhook, offer→Day-1 tracked as its own funnel stage with reminder cadence.

post-offer ghosting = costliest drop-off in frontline hiring

Non-negotiable design principles

Ranked. From the multi-agent research synthesis — argue with these before changing the flow.

Zero login, zero app download, anywhere in the candidate flow
Chat-native and mobile-first; design for 2G/3G reliability
Consent before collection — itemized, timestamped, per category
State persists to the phone number, not a session — resumable for days
Language chosen once, honored in every module incl. reels
Confirm-don't-retype for every OCR/DPI-fetched field
Passive biometrics by default; step-up only on risk flags
Candidate sees 3 states max; adjudication complexity never leaks
Every check has its own progress + SLA clock — never block on the slowest
Offer→Day-1 is a first-class tracked stage with nudge cadence
Two-tier status architecture (Checkr pattern): the candidate chat shows In Progress / Needs Your Attention / Cleared. The ops console (tab 4) holds the full adjudication state machine — risk scores and discrepancy notes never reach the candidate UI.
